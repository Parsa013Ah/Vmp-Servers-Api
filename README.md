# Ph13 VMP API

ی اسکریپت ساده که از سایت vmp اطلاعات سرور و پلیر هاشو میگیره و بهت تحویل میده

با این می‌تونی سایت بسازی، بات بنویسی، یا هر چیز دیگه‌ای که به لیست سرور و پلیر نیاز داره.

## چی داره

- لیست همه سرورهای VMP با فیلتر و مرتب‌سازی
- لیست پلیرهای هر سرور
- جستجوی پلیر توی همه سرورها با اسم یا شناسه (steam hex، license، vmp id، discord)
- آمار کلی
- کش ۶۰ ثانیه‌ای که الکی به VMP درخواست نزنه

> **نکته:** این روش کاملا لحظه‌ای و دقیق نیست و ممکنه یه کم تاخیر داشته باشه. اگه برای سرور خودت می‌خوای، جای این اسکریپت، از اسکریپتی که مستقیم از سرور خودت پلیرها رو می‌گیره استفاده کن. این API فقط از بیرون به داده‌های عمومی VMP نگاه می‌کنه و ممکنه با چند ثانیه تا چند دقیقه تاخیر آپدیت بشه.

## نصب

Node 18 به بالا لازم داری چون از `fetch` خودش استفاده می‌کنه.

```bash
npm install
npm start
```

به صورت پیش‌فرض روی پورت `3000` بالا میاد. اگه پورت دیگه‌ای می‌خوای:

```bash
PORT=8080 npm start
```

برای حالت توسعه که با هر تغییر ری‌استارت بشه:

```bash
npm run dev
```

## Endpoint ها

### گرفتن لیست سرورها

```
GET /api/servers
```

پارامترهایی که می‌تونی بدی (همه اختیاری):

| پارامتر | توضیح |
|---------|-------|
| `q` | سرچ توی اسم، تگ، آی‌دی |
| `gametype` | فیلتر بر اساس نوع گیم‌تایپ |
| `locale` | فیلتر بر اساس زبان |
| `boosted` | `true` یا `false` برای فیلتر سرورهای بوست‌شده |
| `online` | `true` که فقط سرورهای دارای پلیر رو بده |
| `sort` | یکی از `players_desc`, `players_asc`, `max_desc`, `name_asc`, `boost_desc`. پیش‌فرض `players_desc` |
| `limit` | تعداد نتیجه |

مثال:

```
/api/servers?boosted=true&sort=boost_desc&limit=20
/api/servers?q=example
/api/servers?gametype=RolePlay&online=true
```

### اطلاعات یه سرور با پلیرهاش

```
GET /api/servers/:id
```

مثلا:

```
/api/servers/abc123
```

برمی‌گردونه:

```json

  "id": "abc123",
  "hostname": "Example RP | Season 1",
  "gametype": "ESX Legacy",
  "mapname": "San Andreas",
  "clients": 12,

  "players": [
    {
      "id": 1,
      "name": "PlayerOne",
      "ping": 42,
      "identifiers": [
        "vmp:10001",
        "steam:110000100000001",
        "license:000000000000000001"
      ]
    },
    {
      "id": 2,
      "name": "PlayerTwo",
      "ping": 67,
      "identifiers": [
        "vmp:10002",
        "steam:110000100000002",
        "license:000000000000000002"
      ]
    }

```

### فقط پلیرهای یه سرور

```
GET /api/servers/:id/players
```

مثل قبلیه ولی فیلدهای اضافه سرور رو نمی‌ده.

### جستجوی پلیر

```
GET /api/search?q=...
```

پارامترها:

| پارامتر | توضیح |
|---------|-------|
| `q` | اجباری. اسم پلیر یا بخشی از شناسه |
| `includeEmpty` | اگه `true` باشه، سرورهای خالی رو هم اسکن می‌کنه (پیش‌فرض `false`) |
| `limit` | سقف تعداد نتیجه، حداکثر ۵۰۰، پیش‌فرض ۱۰۰ |

مثال با اسم:

```
/api/search?q=Player
```

با steam hex:

```
/api/search?q=110000100000001
/api/search?q=steam:110000100000001
```

با vmp id:

```
/api/search?q=10001
/api/search?q=vmp:10001
```

با license:

```
/api/search?q=000000000000000001
```

خروجی:

```json
{
  "query": "Player",
  "scannedServers": 30,
  "totalResults": 2,
  "results": [
    {
      "player": {
        "id": 1,
        "name": "PlayerOne",
        "ping": 42,
        "identifiers": ["vmp:10001", "steam:110000100000001"]
      },
      "server": {
        "id": "abc123",
        "hostname": "Example RP | Season 1",
        "clients": 12,
        "maxClients": 128
      },
      "matchType": "name",
      "scannedAt": "2026-09-30T12:34:56.789Z"
    }
  ]
}
```

فیلد `matchType` می‌تونه اینا باشه:

- `name` — با اسم پلیر مچ شده
- `id-exact` — شناسه دقیقا یکی بوده
- `id-partial` — بخشی از شناسه مچ شده
- `id` — از طریق آیدی داخلی پلیر مچ شده

## نکته درباره کش

هر درخواست به VMP با یه کش **۶۰ ثانیه‌ای** ذخیره می‌شه. یعنی اگه ۱۰ بار پشت سر هم لیست سرورها رو بخوای، فقط بار اول از VMP گرفته می‌شه و بقیه از حافظه. این هم برای تو سریع‌تره هم VMP رو اذیت نمی‌کنه.

اگه می‌خوای داده تازه بگیری، ۶۰ ثانیه صبر کن یا سرور رو ری‌استارت کن.

## درباره اسکن پلیرها

وقتی `/api/search` صدا زده می‌شه، API می‌ره همه سرورهای فعال رو یکی یکی چک می‌کنه و پلیرشون رو با کوئری مچ می‌کنه. برای اینکه هم سریع باشه هم VMP رو نترکونه:

- ۶ تا درخواست همزمان بیشتر نمی‌ره
- هر درخواست ۸ ثانیه تایم‌اوت داره
- سرورهای خالی به صورت پیش‌فرض اسکن نمی‌شن (با `includeEmpty=true` می‌تونی مجبورش کنی)
- جواب‌ها کش می‌شن، پس اگه دو بار پشت سر هم جستجو کنی، بار دوم خیلی سریع‌تره

اگه سرورت روی یه هاست ضعیفه، عدد `SCAN_WORKERS` توی `server.js` رو کمتر کن.

## ساختن کلاینت برای خودت

اگه یه سایت جدا داری که می‌خوای به این وصل بشی، فقط کافیه به این API درخواست بزنی. CORS بازه و محدودیتی نیست.

مثلا توی جاوااسکریپت:

```js
const res = await fetch("http://your-api.com/api/servers?online=true");
const { servers } = await res.json();

for (const s of servers) {
  console.log(s.hostname, s.clients + "/" + s.maxClients);
}
```
